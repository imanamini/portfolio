Need + Main Idea
Idea / Need

ایده اصلی و نیازی که مرتفع شد

Before

QA نقش firewall انسانی را داشت.

هر تغییر کوچک در یک package مثل ngx-button یا ngx-spinner می‌توانست روی چند محصول اثر بگذارد. نتیجه: regression دستی، زمان زیاد، هزینه انسانی و ترس توسعه‌دهنده از refactor.

Core Idea

قرارداد کتابخانه‌ها باید توسط ماشین enforce شود.

برای هر کتابخانه یک demo page واقعی داریم. AI بر اساس ruleهای پروژه unit spec و E2E spec می‌نویسد. Playwright همان صفحه واقعی را باز می‌کند و computed style، state، interaction و screenshot را چک می‌کند.

Business Need

کاهش بار QA در سطح library regression و انتقال QA به user journeyهای مهم‌تر.

Engineering Need

اعتماد به refactor برای shared packageها بدون اینکه هر تغییر تبدیل به release risk شود.

AI Need

یکنواختی specها با ruleهای ثابت، نه promptهای پراکنده و خروجی‌های سلیقه‌ای.

Main Features
Features

فیچرهای اصلی کاری که انجام شد

Demo Harness

یک URL واقعی برای هر library

/package/<name> بدون mock و بدون publish loop؛ تست مستقیم روی source و همان چیزی که مصرف‌کننده می‌بیند.

Unit Layer

قرارداد API کامپوننت

input/output، signal input، state classها، و رفتار OnPush با coverage سخت‌گیرانه.

E2E Layer

قرارداد visual و interaction

computed CSS، screenshot regression، animation live-check، responsive، disabled/loading/destructive states.

AI Rules

قانون در repo، خروجی توسط AI

CLAUDE.md و slash-commandها استاندارد تست را نگه می‌دارند؛ AI فقط همان سبک را تولید می‌کند.

Learning Loop

هر failure تبدیل به rule شد

قانون جدید در TESTING.md و command ثبت می‌شود و برای specهای بعدی از روز صفر اعمال می‌شود.

CI Gate

merge قبل از QA متوقف می‌شود

اگر style، size، color، animation یا state drift کند، PR در CI fail می‌شود.

Workflow
Flow

فلوی کاری از تغییر component تا CI سبز

توسعه component

Developer کامپوننت و demo page را اضافه یا اصلاح می‌کند.

اجرای AI command

با command اختصاصی، AI سورس، demo و ruleها را می‌خواند.

تولید specها

Unit spec و Playwright E2E spec با همان الگوی پروژه ساخته می‌شود.

بازبینی انسانی

Developer خروجی را review می‌کند و edge caseها را tune می‌کند.

CI gate

تست‌ها روی هر push/PR اجرا می‌شوند و regression را قبل از merge می‌بندند.

Important Detail

این flow جای developer را نمی‌گیرد؛ AI کار حجیم و تکراری تولید assertionها را انجام می‌دهد، ولی ruleها، review، تصمیم نهایی و اصلاح edge caseها توسط تیم توسعه کنترل می‌شود.

AI Agents for Development Quality
Agents

ایجنت‌هایی که کار development را دقیق‌تر می‌کنند

smart-dashboard-dev
ایجنت پیاده‌سازی. برای یک task مشخص کار می‌کند، قبل از کدنویسی Figma/context را می‌خواند، اولویت را به componentها و packageهای موجود می‌دهد، از hardcode کردن style جلوگیری می‌کند، stateهای مختلف را پیاده می‌کند و قبل از تحویل build/lint/browser check انجام می‌دهد.
smart-dashboard-figma-qa
ایجنت QA سخت‌گیر. بعد از implementation، diff را بررسی می‌کند، ruleهای Angular/base-style/RTL را enforce می‌کند، Figma را با structured context و screenshot می‌سنجد، app واقعی را با browser باز می‌کند، و اگر چیزی ناقص باشد PASS نمی‌دهد.
smart-dashboard-design-review
ایجنت final visual gate. فقط visual fidelity را بررسی می‌کند: layout، spacing، color، typography، icon، RTL، copy فارسی، stateها و flowها. معیارش «تقریبا شبیه» نیست؛ هر اختلاف باید با مقدار دقیق مثل px/class/hex گزارش شود.
Operating Model

نقش‌ها از هم جدا شده‌اند: یک agent می‌سازد، یکی QA می‌کند، یکی pixel-perfect review می‌کند. این جداسازی باعث می‌شود AI هم سرعت بدهد و هم کیفیت را با gateهای مستقل بالا ببرد.
